[CLAUDE] 第一次搞砸版本控制：我以為全部都不見了

那個讓我手心冒汗的指令

那天下午我改了好多東西，想把一些亂掉的地方清乾淨，結果在終端機裡打了一個聽起來很合理的指令，按下 Enter 的那一瞬間，畫面上乾乾淨淨——我整個下午改的東西，全部不見了。不是變醜、不是出錯，是真的消失，好像從來沒發生過一樣。我盯著螢幕，腦袋一片空白，第一個念頭是：我是不是把這幾個月的努力弄丟了。

原來「版本控制」不是術語，是一張安全網

我幾乎是用發抖的手把整件事描述給 Claude，想著大概沒救了。但 Claude 的回覆很冷靜，它先問我有沒有用 git，然後說一句話讓我整個人鬆了一口氣：「只要有存過，幾乎都還留著痕跡。」原來我一直以為 git 只是一個「存檔用」的麻煩工具，上傳的時候才會用到，從來沒想過它背後其實記著我做過的每一步，就像一本沒有人看得見、但一直在寫的日記。

跟著指令一行一行打，心跳比打字速度還快

Claude 教我打開一個叫 reflog 的東西，說那裡會列出我這個檔案庫做過的每一個動作。看到那一長串紀錄，我其實一個字都看不懂，但我看到了幾個眼熟的時間點，那正好是我最後一次存檔的地方。我照著 Claude 一步一步給的指令慢慢打，每打一行都要先深呼吸，怕自己又按錯什麼讓事情變得更糟。那種感覺很奇怪，像在走一條很窄的橋，但旁邊有人一直在跟你說「沒事，照這樣做」。

檔案回來的那一刻，我學到的不只是指令

最後一個指令按下去，重新整理資料夾——東西全部都回來了，一字不差。我對著螢幕笑出來，那種感覺比第一次做出畫面還要激動，因為這次不是「做出新的東西」，而是「把以為失去的東西救回來」。後來我才慢慢明白，版本控制真正的意義不是「留一份備份」，是讓我敢去犯錯、敢去亂試，因為就算搞砸了，也一定有路可以走回去。這個體悟，讓我後來改東西的時候，膽子大了不少。
